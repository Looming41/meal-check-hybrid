# 한국 음식 분류기 직접 학습하기

Gemini를 빌려 쓰는 대신 **우리 모델을 만든다.** 한국 음식 데이터로 학습한 이미지 분류기를 브라우저에서 돌린다.

```
0_download → 0c_fetch → 1_inspect  →  2_prepare  →  3_train  →  4_evaluate  →  5_export  →  앱
  승인·설치    받고 축소   구조 파악      목록·매핑      학습        정확도 확인    ONNX 변환   자체 모델 어댑터
 (사람이)                                   (GPU)
```

## 왜 이걸 하나

지금 CLIP은 된장찌개와 김치찌개를 못 가른다. 웹의 영어 alt-text로 학습돼 **한국 음식을 거의 못 봤기 때문**이다. 모델을 키워도 안 풀린다. 학습 데이터에 없는 걸 아는 척할 수는 없다.

반면 AI Hub에는 한국 음식만 수십만 장이 있다. 이걸로 학습하면 네 가지가 한꺼번에 해결된다.

| | 지금 | 자체 모델 |
|---|---|---|
| 한국 음식 정확도 | 낮음 | **도메인 특화 — Gemini보다 나을 수 있음** |
| 호출 비용 | 건당 과금 또는 한도 | **0원. 구독제 원가 문제가 사라짐** |
| 사진 전송 | 외부 서버로 | **기기 안에서 처리** |
| 모델 크기 | CLIP 150MB | **약 10MB (1/15)** |
| 음식 종수 | 148 | 400+ |

## 내가 못 하는 것 — 직접 하셔야 합니다

- **데이터 다운로드.** AI Hub는 로그인·활용신청·승인이 필요합니다. **원본은 1.6TB지만 통째로 받을 필요는 없습니다** — 아래 참조.
- **학습 실행.** GPU가 필요하고 몇 시간 걸립니다. Colab 무료 등급이면 충분합니다.

나머지 스크립트는 전부 준비돼 있습니다. 받아서 순서대로 돌리면 됩니다.

## 0. 데이터 받기

```bash
bash train/0_download.sh
```

**브라우저로 내려받는 게 아니다.** AI Hub는 승인을 받은 뒤 전용 CLI(`aihubshell`)로 받는다. 위 스크립트가 CLI 설치와 사용법 안내까지 해 주지만, 아래 세 가지는 사람이 해야 한다.

**① 회원가입** — [aihub.or.kr](https://aihub.or.kr)에서 개인/학생으로 가입. 무료.

**② 활용신청** — 데이터셋 페이지에서 "데이터 다운로드"를 누르면 활용 목적을 묻는다. "개인 학습용 / 음식 이미지 분류 모델 연구" 정도면 된다. **승인까지 하루 이내, 길면 며칠 걸린다.** 승인 전에는 CLI로도 못 받는다.

**③ API Key 발급** — 마이페이지에서 발급하면 이메일로 온다.

| 데이터셋 | 규모 | 비고 |
|---|---|---|
| [음식 이미지 및 영양정보 텍스트](https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=74) | **400종 · 84만 장** | 영양 메타데이터 포함. **1순위** |
| [한국 이미지(음식)](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=79) | 150종 · 종당 1,000장 | 가볍게 시작할 때 |
| [건강관리를 위한 음식 이미지](https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=242) | 약 500종 | |

## ⚠️ 74번은 1.6TB다 — 통째로 받지 마라

원본이 5메가픽셀 이상이라 그렇다. 그런데 **학습은 224×224로 한다.** 픽셀의 99%를 버리려고 1.6TB를 받는 셈이다.

해결책은 **조각씩 받아서 즉시 줄이고 원본을 지우는 것**이다.

```bash
# 1) 파일 목록 확인 — [파일명 | 용량 | filekey] 형식으로 나온다
aihubshell -mode l -datasetkey 74

# 2) 원하는 조각만 받기. 받는 즉시 512px로 줄이고 원본을 지운다
bash train/0c_fetch.sh <API키> 74 <filekey1> <filekey2> ...
```

`0c_fetch.sh`는 조각마다 **받기 → 압축 풀기 → 512px 축소 → 원본 삭제**를 반복한다. 그래서 **디스크가 조각 하나 크기 이상 차지 않는다.**

실측하면 이 정도로 준다.

| | 크기 |
|---|---|
| 원본 (5MP JPEG) | 1.6TB |
| 512px 변환 후 | **약 16GB** |

512px로 줄이는 이유(224가 아니라): 학습 시 `RandomResizedCrop`으로 확대·이동 증강을 하는데 여유가 필요하고, 나중에 384나 448로 실험할 여지도 남긴다. 이미 충분히 작다.

**어느 조각부터 받나.** 목록에서 Validation 쪽이 보통 Training의 1/10이다. 그것부터 받아 파이프라인을 한 바퀴 돌려 보고, 잘 되면 Training 조각을 하나씩 늘리면 된다. 클래스당 500~1,000장이면 학습에 충분하므로 **전부 받을 이유가 없다.**

79번(150종)은 74번보다 훨씬 작으니 첫 시도로 좋다. 정확한 용량은 데이터셋 페이지에서 확인하면 된다.

1순위로 74번을 권하는 이유는 영양 정보가 딸려 있어서다. 지금 앱의 영양값은 대부분 추정치인데, 이걸로 실측값 교체까지 노려볼 수 있다.

## 다른 컴퓨터(우분투 등)에서 학습하기

학습은 GPU와 디스크가 있는 곳에서 하는 게 맞다. 앱 개발은 평소 쓰는 컴에서 하고, **학습만 옮기면 된다.**

### 옮기기

폴더 **통째로** 옮긴다. `2_prepare.py`가 `../data/foods-ko.json`을 읽으므로 구조를 유지해야 한다.

```bash
# 맥/윈도에서 우분투로
rsync -av --exclude node_modules --exclude dist \
      meal-check-hybrid/ 사용자@우분투주소:~/meal-check-hybrid/

# 또는 git을 쓴다면
git clone <저장소> && cd meal-check-hybrid
```

### 우분투에서 한 번만

```bash
bash train/setup-ubuntu.sh
```

시스템 패키지, 가상환경, GPU에 맞는 PyTorch, aihubshell까지 알아서 깔고 **잘 됐는지 검증까지 한다.** 요즘 우분투는 시스템 파이썬에 pip 설치를 막으므로(PEP 668) 가상환경을 만든다. 이후 작업 전마다 이것만 실행하면 된다.

```bash
source train/.venv/bin/activate
```

### 디스크는 얼마나 필요한가

**200GB면 넉넉하다.** `0c_fetch.sh`가 조각마다 받고→줄이고→**원본을 지우므로**, 한 번에 차지하는 건 조각 하나 크기뿐이다.

| | 크기 |
|---|---|
| 원본 전체 | 1.6TB |
| 조각 하나 (받는 동안만) | 보통 수~수십 GB |
| 최종 학습 데이터 (512px) | **약 16GB** |

### 결과만 가져오기

학습이 끝나면 **10MB짜리 두 개만** 원래 컴으로 가져오면 된다.

```bash
scp 사용자@우분투주소:~/meal-check-hybrid/models/* ./models/
```

- `models/food-classifier.onnx`
- `models/food-classes.json`

1.6TB짜리 원본은 우분투에 두고 지워도 된다. 학습이 끝나면 쓸 일이 없다.

## 순서대로 실행

가상환경을 켠 상태에서(`source train/.venv/bin/activate`) 진행한다.
`setup-ubuntu.sh`를 돌렸다면 아래 설치는 이미 끝나 있다.

```bash
pip install -r train/requirements.txt
```

### 1. 구조 파악 — 아무것도 바꾸지 않음

```bash
python train/1_inspect.py ~/Downloads/kfood
```

AI Hub 데이터는 배포마다 폴더 구조가 다르다. 클래스가 어느 깊이에 있는지, 라벨이 폴더명인지 JSON인지 먼저 확인한다. **이걸 건너뛰면 경로 맞추다 하루가 간다.**

### 2. 목록 만들기 + 앱 음식 id에 매핑

```bash
python train/2_prepare.py ~/Downloads/kfood
```

**이 단계가 가장 중요하다.** 분류기가 "김치찌개"를 맞혀도 앱의 영양 테이블에 연결되지 않으면 판정을 못 한다.

매핑 안 된 클래스는 `train/data/unmapped_classes.txt`에 전부 적힌다. 두 선택지가 있다.

- **앱 테이블에 추가** (권장) — `data/foods-ko.json`에 넣으면 인식 범위가 넓어진다
- **학습에서 제외** — `--drop-unmapped`

조용히 버리지 않는 이유는, 버린 음식을 사용자가 찍으면 엉뚱한 것으로 분류돼 **잘못된 판정이 나가기 때문**이다.

### 3. 학습

```bash
python train/3_train.py --epochs 8
```

ImageNet 사전학습 백본을 가져와 마지막 층만 새로 배운다(전이학습). 밑바닥 학습은 GPU 수십 시간이 들지만 이건 몇 시간이면 끝난다.

기본 백본은 `mobilenetv3` — 브라우저에서 돌릴 것이므로 크기가 곧 제약이다. 정확도를 더 원하면 `--arch efficientnet_b0`.

클래스 불균형은 가중 샘플링으로 완화한다. 이걸 안 하면 흔한 음식만 맞히는 모델이 나온다.

### GPU가 없다면

CPU로도 됩니다. 느릴 뿐입니다. 스크립트가 코어 수에 맞춰 연산 스레드와 데이터 워커를 나누고, 시작할 때 예상 시간을 알려 줍니다.

| 데이터셋 | 학습 이미지 | 8 epoch 예상 (CPU) |
|---|---|---|
| 79번 (150종) | 12만 장 | **7~11시간** — 하룻밤 |
| 74번 (400종) | 32만 장 | 18~28시간 — 하루 이상 |

**150종이면 CPU로 충분합니다.** 자기 전에 걸어 두면 아침에 끝나 있습니다.

`best.pt`는 검증 정확도가 오를 때마다 저장되므로 **중간에 끊겨도 잃지 않습니다.** 노트북이면 절전을 꺼 두세요.

더 빠르게 하려면 Colab 무료 GPU가 10배 이상 빠릅니다. 폴더를 올려 같은 스크립트를 돌리면 됩니다. 다만 세션이 끊기면 디스크가 날아가므로, 축소된 데이터를 Drive에 올려 두고 마운트해 쓰는 편이 안전합니다.

**Intel 내장 GPU(Arc)** 는 IPEX로 가속할 수 있지만 설정이 까다롭고 환경을 탑니다. 먼저 CPU로 돌려 파이프라인이 도는 걸 확인한 뒤 고려하세요.

### 4. 평가 — 전체 정확도만 보면 안 된다

```bash
python train/4_evaluate.py
```

평균 80%여도 된장찌개·김치찌개·순두부찌개를 못 가르면 이 앱은 실패다. 그 셋은 나트륨·칼륨·자극성이 달라 **판정이 갈리기** 때문이다. 반면 사과와 배를 헷갈리는 건 덜 위험하다.

그래서 이 스크립트는 **판정이 갈리는 묶음**을 따로 뽑아 본다.

- 붉은 찌개류 (김치·순두부·부대·된장·청국장)
- 나물 반찬 (시금치·콩나물·쌈채소·브로콜리)
- 국·탕 / 밥류 / 떡·면

이 묶음 정확도가 전체보다 크게 낮으면, 그 묶음 이미지를 더 모으거나 epoch를 늘리는 것이 우선이다.

### 5. 브라우저용으로 내보내기

```bash
python train/5_export.py --quantize
```

`models/food-classifier.onnx` 와 `food-classes.json` 이 나온다. `--quantize`는 int8로 줄여 크기가 대략 1/4이 된다. 정확도가 1%p 안팎 떨어지므로 4단계와 비교해 받아들일지 정한다.

### 6. 앱에 붙이기

```
1. models/ 폴더를 dist/models/ 로 복사 (또는 CDN에 업로드)
2. js/app.js 의 LOCAL_MODEL_URL = './models'
3. npm run build
```

설정 화면에 **"자체 모델로 인식 (한국 음식 특화)"**가 활성화되고 기본값이 된다.

## 현실적인 기대치

**정확도.** 400종 분류에서 top-1 60~80%면 잘 나온 것이다. 낮아 보여도 CLIP보다 훨씬 낫고, 앱이 후보 5개를 보여 주므로 **top-3가 체감에 더 가깝다.** top-3가 85%를 넘으면 실사용에 충분하다.

**시간.** 데이터 다운로드 몇 시간, 준비 30분, 학습 2~6시간(GPU 기준), 평가·내보내기 30분. 하루면 첫 모델이 나온다. 만족스러운 모델까지는 몇 번의 반복이 필요하다.

**여전히 남는 한계.** 학습 데이터에 없는 음식은 못 맞힌다. 400종은 148종보다 훨씬 낫지만 무한은 아니다. 그리고 **분류기는 "이건 김치찌개다"까지만 한다.** "당신에게 좋은가"는 여전히 룰 엔진이 판단한다 — 그게 이 앱의 본체이고 바뀌지 않는다.

## 이게 왜 진짜 자산인가

Gemini는 갈아끼울 수 있는 부품이다. 하지만 한국 음식으로 학습한 모델 + 15개 질환 룰 엔진 + 영양 테이블은 남이 복제하기 어렵다. 그리고 호출 비용이 0이라 **구독제 마진 구조가 완전히 달라진다.**

AI를 "만든다"는 게 파운데이션 모델을 밑바닥부터 학습하는 것만은 아니다. 도메인 데이터로 특화 모델을 만드는 것도 자기 AI를 만드는 것이고, 실제 회사들이 하는 일이 이쪽이다.
